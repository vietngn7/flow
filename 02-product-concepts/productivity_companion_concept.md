# 🎯 Productivity Companion - Концепция продукта

## Ключевые принципы
- **LLM как помощник, НЕ автопилот** - человек принимает решения
- **Структурированный подход** - brain dump → категоризация → приоритизация
- **Контекстная помощь** - LLM помогает только когда есть достаточно информации

---

## 📱 Основные функции

### 1. Brain Dump Assistant

```
Пользователь: "надо презу сделать, позвонить маме, купить молоко,
               разобраться с багом в проде, встреча с командой в 3"

LLM автоматически:
├─ Категории: Work / Personal / Urgent
├─ Контекст: "баг в проде" → высокий приоритет
├─ Таймфреймы: "встреча в 3" → time-bound
└─ Предложения: "Похоже 'баг в проде' срочный - хотите добавить в топ-3?"
```

**Важно**: LLM только категоризирует и подсвечивает, НЕ решает за пользователя!

### 2. Daily Top-3 Coach

**Цель**: Минимальный friction при выборе топ-3

**Quick Select Mode** (основной):

```
После brain dump:
┌─ TOP-3 QUICK SELECT ────────┐
│ Тапни 3 самые важные задачи: │
│                              │
│ [ ] Презентация              │
│ [ ] Баг в проде              │
│ [ ] Позвонить маме           │
│ [ ] Купить молоко            │
│ [ ] Встреча с командой       │
│ [ ] Рефакторинг легаси       │
│                              │
│ [Confirm Top-3]              │
└──────────────────────────────┘

User: [выбирает 3 задачи]

Bot: "Топ-3 выбраны! Типы задач?"

┌─ TASK TYPES ─────────────────┐
│ 1. Презентация:              │
│    🎯 Execution (сделать)    │
│    🔬 Exploration (изучить)  │
│    📚 Learning (научиться)   │
│                              │
│ 2. Баг в проде: [тип?]       │
│ 3. Звонок маме: [тип?]       │
└──────────────────────────────┘

User: "преза - execution, баг - exploration, звонок - execution"

Bot: "Отлично!
     - Exploration задачи = таймбокс, не обязательно завершить
     - Для бага даю 1ч исследования. Ок?"
```

**Типы задач**:
- **🎯 Execution** - конкретный результат, надо завершить
- **🔬 Exploration** - исследование, таймбокс важнее результата
- **📚 Learning** - обучение, измеряется временем + инсайтами

**Опциональный Deep Mode** (если пользователь не уверен):

```
User: "/top3 --help"

Bot запускает сократовский диалог:
"Какая задача самая важная? Почему?"
[Классический коучинг из предыдущей версии]
```

**Механика**: По умолчанию - кнопки (быстро), опционально - диалог (глубже).

### 3. CP (Critical Path) & TMP (Time Management Plan) Planner

**TMP = Critical Path + Buffers для interruptions**

После выбора топ-3, LLM спрашивает про interruptions:

```
Top-3 выбраны:
1. Презентация (execution, 2-3ч)
2. Баг в проде (exploration, 1ч)
3. Позвонить маме (execution, 15мин)

Bot: "Сколько обычно незапланированных дел в день?"

Quick replies:
[Мало (0-1)] [Средне (2-3)] [Много (4+)]

User: [тапает "Средне (2-3)"]

Bot генерирует TMP:
┌─ TIME MANAGEMENT PLAN ──────┐
│ 10:00-13:00 → Преза         │ ← Critical Path
│ 13:00-14:00 → Обед          │
│ 14:00-15:00 → БУФЕР         │ ← для interruptions
│ 15:00-16:00 → Баг (explore) │
│ 16:00-16:30 → БУФЕР         │ ← для interruptions
│ 16:30-16:45 → Звонок маме   │
│ 16:45-17:00 → Slack time    │
└─────────────────────────────┘

"Добавил 1.5ч буферов на прерывания.
 Встреча в 15:00 учтена. Ок?"
```

**Принципы планирования**:
- Critical Path = топ-3 задачи + dependencies
- Buffers = защита от interruptions (из документов)
- Deep work утром (когда энергия выше)
- Exploration задачи = строгий таймбокс
- Slack time в конце дня

**Если interruption случается**:
```
User: "/pause внезапная встреча"
Bot: "Ок, буфер 14:00-15:00 использован.
     План скорректирован: баг сдвигается на 15:30"
```

### 4. Interruption Resume (Telegram Bot)

**MVP: Без LLM! Простой state storage**

Быстрая команда `/pause` в телеге:

```typescript
// Структура данных
interface Interruption {
  timestamp: Date;
  currentTask: string;
  interruptionReason?: string;  // опционально
  nextAction?: string;          // опционально
}
```

**UX Flow**:

```
User работает над презой

User: "/pause звонок клиенту"

Bot сохраняет state:
✅ Сохранено:
   Задача: Презентация
   Время: 14:23
   Причина: звонок клиенту

[Continue] → возвращает к презе сразу
```

**Resume flow**:

```
User: "/resume"

Bot показывает последний state:
📌 Последнее прерывание:
   Задача: Презентация
   Прервано: 14:23 (35 минут назад)
   Причина: звонок клиенту

Quick replies:
[Продолжить презу] [Переключиться] [Что дальше?]
```

**Когда нужен LLM**:
- Если пользователь не помнит контекст (давно прервался)
- Анализ паттернов: "Ты часто прерываешься на звонки после обеда"

**Фишка**: Моментальное сохранение контекста, 0 cognitive load

### 5. "Stuck" Handler - Помощь со сложными задачами

**Проблема**: Мега сложные задачи, которые не хочется делать, но нужно

**Цель**: Минимальный friction для начала + снижение psychological resistance

---

#### Вариант A: "Tiniest Possible Step" (Quick Mode)

```
User: "/stuck рефакторинг легаси кода"

Bot: "Застрял? Норм. Какой САМЫЙ маленький шаг сделаешь?"

Quick replies (никакого текста!):
[📖 Почитать код 5мин]
[📝 Написать TODO-список]
[👤 Спросить коллегу]
[🧪 Написать один тест]
[🔍 Погуглить похожие кейсы]

User: [тапает "Почитать код 5мин"]

Bot: "Отлично! Ставлю таймер на 5мин.
     После расскажешь что увидел - это exploration задача."

[Start Timer 5min]
```

**Принцип**: Действие важнее размышлений. Любой шаг > никакого шага.

---

#### Вариант B: "Procrastination Detective"

```
Bot замечает: задача висит 3+ дня без прогресса

Bot: "Рефакторинг висит 3 дня. Что мешает начать?"

Quick replies:
[❓ Не знаю с чего начать]
[😰 Страшно сломать]
[😴 Скучная задача]
[📚 Не хватает инфы]
[⏰ Нет времени]

User: [тапает "Страшно сломать"]

Bot: "Понял. Safety-first подход:

     Шаг 1: Сделай safety net (30мин)
     ├─ Бэкап текущей ветки
     ├─ Напиши 2-3 теста на текущее поведение
     └─ Создай отдельную feature-ветку

     После этого будет не страшно. Начнем с safety net?"

[Yes, let's go] [Tell me more]
```

**Паттерны блокеров**:
- "Не знаю с чего начать" → декомпозиция на мини-шаги
- "Страшно сломать" → создание safety net
- "Скучная задача" → gamification или pairing
- "Не хватает инфы" → research task (exploration mode)

---

#### Вариант C: "Task Context Capture" (минимум friction)

```
User: "/stuck рефакторинг легаси кода"

Bot: "Хочешь быстрый совет или разобраться глубже?"

[⚡️ Quick tips] [🔍 Deep dive]

Если Quick tips:
Bot: "3 способа начать ПРЯМО СЕЙЧАС:
     1. 5мин read-only кода (ничего не меняй)
     2. Напиши список страшных мест
     3. Попроси code review у коллеги

     Какой попробуешь?"

Если Deep dive:
Bot открывает мини-форму (inline):
┌─ TASK CONTEXT ──────────────┐
│ Что уже пробовал?           │
│ [Skip / Написать]           │
│                             │
│ Что самое страшное?         │
│ [Skip / Написать]           │
│                             │
│ [Get Personalized Help]     │
└─────────────────────────────┘
```

**Фишка**: Пользователь сам выбирает уровень погружения

---

#### Когда задача начата - отслеживание прогресса

```
После 30мин работы:

Bot: "Как идет рефакторинг? Что узнал?"

Quick replies:
[✅ Разобрался, продолжаю]
[🤔 Еще не ясно]
[😫 Застрял еще больше]
[💡 Нашел другой подход]

Если "Застрял еще больше":
Bot: "Ок, переключаемся. Execution → Exploration.
     Давай 1ч просто изучить проблему, без решения.
     Записывай вопросы. Завтра обсудим с командой."
```

**Из документов**:
- Micro-goals
- Experimentation (пробовать разные подходы)
- Switching modes (execution ⟷ exploration)

---

#### Интеграция с Top-3

```
Если сложная задача в топ-3:

Bot при планировании:
"Рефакторинг - сложная задача. Хочешь разбить на подзадачи?"

[Yes] [No, I'll manage]

Если Yes:
Bot: "Какой первый маленький шаг?"
[предлагает варианты из Tiniest Step]
```

**Принцип**: Не заставлять делать всю задачу сразу, помочь начать с чего-то маленького

```
LLM: "У тебя 3 задачи. Преза требует креативности - лучше утром.
      Баг в проде - алгоритмическая работа, можно и после обеда.
```

### 7. Pattern Recognition

```
После недели использования:
LLM: "Заметил, что по вторникам у тебя всегда падает продуктивность
      после 15:00. Может ставить сложные задачи только на утро?"
```

### 8. Distraction Guard

```
User добавляет новую задачу в топ-3:
LLM: "Стоп! У тебя уже есть топ-3. Эта задача срочнее презы?
      Или добавить в backlog?"
```

## 🧠 Архитектура LLM взаимодействия

### Роли LLM:

1. **Categorizer** (автоматический) - сортирует brain dump по категориям/срочности
2. **Coach** (опциональный) - задаёт вопросы для топ-3 в deep mode
3. **Planner** (предлагает) - генерирует TMP с буферами
4. **Stuck Helper** (советует) - помогает начать сложные задачи
5. **Pattern Analyzer** (наблюдает) - находит паттерны в поведении

### Границы LLM:

**✅ LLM может**:
- Категоризировать задачи из brain dump
- Предлагать варианты и задавать вопросы
- Генерировать расписание (TMP)
- Советовать micro-steps для сложных задач
- Анализировать паттерны прерываний

**❌ LLM НЕ может**:
- Выбирать топ-3 за пользователя
- Удалять задачи без подтверждения
- Принимать решения о приоритетах
- Автоматически менять план без согласования

**🤝 Без LLM в MVP**:
- `/pause` / `/resume` - простой state storage
- Таймеры для задач
- Базовое отслеживание прогресса

## 💡 Инсайты из документов

### Применение принципов:

1. **Planning Fallacy** → LLM спрашивает: "Сколько РЕАЛЬНО нужно времени?"
2. **Sunk Cost** → Если задача долго висит: "Может отказаться?"
3. **Parkinson's Law** → Добавляет дедлайны: "Дам тебе 90мин на презу?"
4. **MIT (Most Important Tasks)** → Это и есть топ-3
5. **Timeboxing** → Автоматически в CP/TMP планировании

## 🚀 MVP фичи для старта

### Phase 1: Core Workflow (2-3 недели)

**Must-have**:
1. ✅ Brain dump с LLM категоризацией (Work/Personal/Urgent)
2. ✅ Top-3 Quick Select (inline buttons, task types)
3. ✅ Простой TMP генератор (с буферами на interruptions)
4. ✅ `/pause` / `/resume` БЕЗ LLM (state storage only)

**Tech stack**:
- Telegram Bot API (python-telegram-bot)
- SQLite для хранения tasks/state
- LLM API для категоризации (OpenAI/Anthropic)

**Success metrics**:
- Пользователь делает brain dump < 2мин
- Top-3 выбирается < 1мин (с кнопками)
- План на день готов < 5мин total

---

### Phase 2: Stuck Handling (1-2 недели)

**Features**:
1. ✅ `/stuck` команда с Quick Tips режимом
2. ✅ Procrastination Detective (паттерны блокеров)
3. ✅ Таймеры для exploration задач
4. ✅ Progress check-ins ("Как идет?")

**Измеримая цель**: Снизить время старта сложной задачи с 3 дней до 30 минут

---

### Phase 3: Intelligence Layer (2-3 недели)

**Features**:
1. ✅ Pattern recognition (анализ interruptions)
2. ✅ Energy-aware scheduling
3. ✅ Deep mode для Top-3 (сократовский диалог)
4. ✅ Weekly review с инсайтами

**Nice-to-have**:
- Интеграция с Google Calendar

## 🤔 Открытые вопросы для дизайна

### UX вопросы:

1. **Как часто LLM может "пинать" пользователя?**
   - Риск стать annoying
   - Вариант: пользователь сам настраивает частоту check-ins
   - Или: адаптивно, на основе engagement

2. **Персистентность топ-3**
   - Переносить незавершённые задачи на завтра автоматически?
   - Или спрашивать каждый раз?
   - Как долго хранить backlog?

3. **Notifications strategy**
   - Push когда пора начинать следующую задачу?
   - Напоминания о буферах?
   - Не слишком ли intrusive?

### Технические вопросы:

4. **LLM provider**
   - OpenAI (быстрый, дорогой)
   - Anthropic Claude (умный, средний price)
   - Local model (дешево, но качество?)

5. **Data persistence**
   - Сколько хранить историю задач?
   - Privacy: где хранить данные?
   - Экспорт данных для пользователя?

6. **Интеграции**
   - Google Calendar для встреч?
   - Notion/Todoist sync?
   - Slack для рабочих задач?

### Behavioral questions:

7. **Как измерять успех продукта?**
   - Daily active users?
   - Completion rate топ-3?
   - Retention?
   - User-reported productivity increase?

8. **Monetization**
   - Freemium (базовые фичи free, pattern recognition paid)?
   - Subscription?
   - One-time payment?
